Plan d'integration apres merge

Document perso pour reprendre proprement apres la PR lexer / expansion / parser / heredoc preparation mergee dans dev.

Etat actuel

  • La PR clean a ete mergee dans dev.
  • Le code utile de ma partie est maintenant disponible pour Dounia.
  • Les fichiers perso de notes/tests/html ne doivent pas etre merges dans dev.
  • La branche chloe garde les docs perso pour continuer a travailler.

Ce qui est deja en place cote parser

  • Le lexer cree les tokens word, pipe, redirections et heredoc.
  • Les quotes sont detectees, puis retirees apres expansion.
  • L'expansion gere les variables classiques, $?, les quotes simples/doubles et les cas type $2USER.
  • validate_syntax bloque les erreurs simples avant de parser.
  • parse_tokens existe toujours pour ne pas casser la loop actuelle.
  • parse_tokens_with_env(tokens, env) existe pour la vraie integration heredoc avec expansion.
  • open_redirections ouvre <, >, >> et appelle le heredoc pour <<.
  • Le heredoc lit les lignes avec readline("> "), ecrit dans un pipe, et met le fd de lecture dans cmd->fd_in.

Point important sur heredoc

Le heredoc peut deja fonctionner dans le parser, mais dans le vrai minishell il faut que la loop donne l'environnement au parser. Sinon un heredoc comme cat << EOF avec $USER dedans ne pourra pas expanser correctement dans le flux normal.

Changements a faire apres le merge

1. Brancher le parser avec l'environnement

Dans la loop principale, remplacer l'appel simple par l'appel qui prend l'environnement.

Fichier A verifier avec Dounia Pourquoi
srcs/main.c ou fichier de loop Passer de parse_tokens(shell->token) a parse_tokens_with_env(shell->token, shell->env). Necessaire pour expanser le contenu des heredocs non quotes.

Note : garder parse_tokens comme wrapper est utile, parce que ca evite de casser les tests ou les appels temporaires.

2. Appliquer les redirections sur une commande externe seule

Actuellement, dans les pipelines, set_fds applique deja cmd->fd_in et cmd->fd_out. Par contre, pour une commande externe seule, le child de exec_single_external lance directement exec_external.

A adapter avec Dounia dans srcs/exec/exec_external.c : dans le child, faire les dup2 necessaires avant exec_external.

Cas a tester apres adaptation :

cat < infile
cat << EOF
wc -l << EOF
cat << EOF > outfile

3. Appliquer les redirections sur un builtin seul

Les builtins seuls tournent dans le process parent, donc il faut faire plus attention que pour une commande externe.

Action Pourquoi
Sauvegarder stdin et stdout avec dup. Un builtin seul ne fork pas forcement, donc il ne doit pas casser le terminal.
Appliquer cmd->fd_in / cmd->fd_out avec dup2. Pour que echo test > file, env > file, etc. marchent.
Lancer le builtin. Le builtin ecrit/lit sur les bons fd.
Restaurer stdin et stdout. Pour que le prompt continue a marcher normalement apres.

Cas a tester apres adaptation :

echo hello > /tmp/ms_out
cat /tmp/ms_out
pwd > /tmp/ms_pwd
env > /tmp/ms_env
cd .. > /tmp/ms_cd

4. Clarifier la propriete des fd

A voir avec Dounia pour eviter les doubles close ou les fd oublies.

  • Le parser ouvre les fichiers/redirections et stocke les fd dans t_cmd.
  • L'exec doit utiliser ces fd avec dup2.
  • Apres usage, l'exec ou le cleanup doit fermer les fd restants.
  • Si une redirection remplace une autre, le parser ferme deja l'ancien fd.

5. Verifier la gestion d'erreur

Les erreurs syntaxiques sont cote parser. Les erreurs d'ouverture de fichiers, de pipe, fork, dup2, execve, etc. doivent donner un message clair cote parser/exec.

Cas Message / comportement attendu
cat < missing_file Erreur avec perror ou message proche bash, status non-zero, pas d'exec inutile.
| cat, cat |, cat > Erreur de syntaxe avant exec.
cat << EOF puis Ctrl-D Warning heredoc, pas de crash.

Ce qui touche la partie de Dounia

Ces points doivent etre discutes avant de modifier directement ses fichiers, surtout si elle travaille deja sur la loop et l'exec.

  • main.c / loop : quand appeler parse_tokens_with_env.
  • exec_single_external : appliquer fd_in/fd_out dans le child.
  • exec_builtins ou le dispatcher autour : save/restore fd pour les builtins seuls.
  • Cleanup final : qui ferme les fd ouverts dans t_cmd.
  • Signaux heredoc : surtout Ctrl-C pendant le prompt > .

Ordre conseille pour la suite

  1. Se mettre sur une branche fraiche depuis dev apres le merge de Dounia.
  2. Reverifier que dev compile avant de toucher au code.
  3. Brancher parse_tokens_with_env dans la loop avec Dounia.
  4. Adapter les redirections pour commande externe seule.
  5. Adapter les redirections pour builtin seul avec save/restore.
  6. Tester heredoc dans le vrai minishell.
  7. Faire une passe Norminette sur les fichiers modifies.
  8. Seulement apres, attaquer les signaux heredoc si la base est stable.

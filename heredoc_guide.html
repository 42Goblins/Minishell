Heredoc dans minishell

Fiche pour comprendre le principe avant de coder. Le but est de comprendre ce que bash fait, puis comment on peut le traduire dans notre pipeline lexer -> expansion -> parser -> exec.

1. L'idée simple

Un heredoc, c'est une redirection d'entrée. Au lieu de lire depuis un fichier avec < file, la commande lit depuis un texte que l'utilisateur tape directement dans le terminal.

Exemple :

cat << EOF
hello
world
EOF

Résultat :

hello
world

Le mot EOF est le delimiter. Il sert juste à dire : "j'arrête de lire le heredoc quand je vois exactement cette ligne".

2. Différence avec une redirection classique

Syntaxe Ce que la commande reçoit sur stdin
cat < file.txt Le contenu de file.txt
cat << EOF Les lignes tapées jusqu'à la ligne EOF

Donc pour l'exec, au final, heredoc doit juste devenir un fd d'entrée dans cmd->fd_in, comme une redirection <.

3. Ce que tu peux tester dans bash

Test basique

cat << EOF
salut
test
EOF

Tu dois voir :

salut
test

Le delimiter doit être seul sur sa ligne

cat << STOP
hello
STOP ok
STOP

La ligne STOP ok ne ferme pas le heredoc, parce qu'elle n'est pas exactement égale à STOP.

Heredoc avec une autre commande

wc -l << END
a
b
c
END

Résultat attendu : 3, parce que wc -l lit 3 lignes.

Heredoc dans un pipe

cat << EOF | wc -l
a
b
EOF

Bash lit d'abord le heredoc, puis lance le pipeline. wc -l reçoit donc les lignes envoyées par cat.

4. Expansion dans heredoc

Le heredoc a une règle importante : le delimiter lui-même ne doit pas être expandé. 

cat << $USER

Ici, le delimiter est littéralement $USER, pas la valeur de la variable USER.

Contenu non quoté : expansion oui

cat << EOF
hello $USER
EOF

Dans bash, $USER est remplacé dans le contenu du heredoc, parce que le delimiter EOF n'est pas quoté.

Delimiter quoté : expansion non

cat << 'EOF'
hello $USER
EOF

Ici, $USER reste écrit comme ça, parce que le delimiter est quoté.

Pour notre minishell, ça veut dire qu'on doit garder l'info had_quotes sur le token delimiter assez longtemps pour savoir si on expand ou pas les lignes du heredoc.

5. Où ça se place dans notre minishell

Pipeline actuelle visée :

readline
-> tokenizer
-> expand_tokens
-> remove_quotes_from_tokens
-> validate_syntax
-> parse_tokens
-> launch_exec

Pour heredoc, le point important est que la lecture du contenu doit se faire avant l'exec, dans le parent.

Pourquoi avant l'exec ? Parce que bash prépare les heredocs avant de lancer les commandes, même quand il y a un pipeline.

Version mentale simple :

  1. Le lexer crée un token T_HEREDOC pour <<.
  2. Le token suivant est le delimiter.
  3. L'expansion saute ce delimiter.
  4. Le retrait des quotes nettoie le delimiter.
  5. Le parser voit T_HEREDOC.
  6. Il lit les lignes avec readline("> ").
  7. Il écrit ces lignes dans un pipe ou un fichier temporaire.
  8. Il met le fd de lecture dans cmd->fd_in.
  9. L'exec utilise cmd->fd_in comme pour < file.

6. Pipe ou fichier temporaire ?

Option Principe Avantage Attention
Pipe On écrit le heredoc dans pipefd[1], puis la commande lit pipefd[0]. Pas de fichier à supprimer. Il faut bien fermer les bons côtés du pipe.
Fichier temporaire On écrit dans un fichier caché, puis on le rouvre en lecture. Plus facile à visualiser. Il faut gérer les noms uniques et supprimer le fichier.

Pour notre projet, le pipe est probablement plus propre si on le gère calmement : pas de fichier temporaire, moins de cleanup disque.

7. Cas importants à gérer

  • cat << EOF : cas simple.
  • cat << EOF | wc -l : heredoc dans pipeline.
  • cat << EOF < file : dernière redirection d'entrée gagne.
  • cat < file << EOF : le heredoc final gagne.
  • cat << 'EOF' : pas d'expansion dans le contenu.
  • cat << EOF puis Ctrl-D avant EOF : warning bash-like à prévoir.
  • Ctrl-C pendant heredoc : doit stopper proprement sans tuer le shell parent.

8. Mini modèle mental

Commande :
cat << EOF
hello
EOF

Tokens :
[cat] [<<] [EOF]

Parser :
voit <<
lit les lignes jusqu'à EOF
met le contenu dans un fd
cmd->fd_in = ce fd
cmd_and_args = ["cat", NULL]

Exec :
dup2(cmd->fd_in, STDIN_FILENO)
exec cat

cat lit donc :
hello

Priorites

Majeur1. Builtin exit imprime exit en non-interactif

Mandatory contient 368 KO sur des commandes exit. Dans ces tests, bash ne sort rien sur stdout parce qu'il lit depuis un pipe. Notre builtin exit imprime probablement exit sans verifier isatty(STDIN_FILENO).

[KO] [Mandatory] exit   
   [STDOUT EXPECTED]: ''
   [STDOUT GOT]     : 'exit'

Action proposee : dans le builtin exit, afficher exit seulement si stdin est interactif. C'est le meme principe que celui deja applique dans launch_loop pour Ctrl-D.

Majeur2. Variables unset collees : argument vide/espace parasite

En expansions, $UNEXISTING$UNEXISTING doit disparaitre completement. Notre minishell garde un vide qui devient un espace avant l'argument suivant.

[KO] [Expansions] echo $UNEXISTING$UNEXISTING a
   [STDOUT EXPECTED]: 'a'
   [STDOUT GOT]     : ' a'

Action proposee : verifier la phase expansion/token : quand un token non quote devient vide apres expansion, il doit etre supprime comme argument, pas conserve comme chaine vide, sauf cas quote explicite.

Moyen3. Options des builtins

Beaucoup de KO mandatory concernent pwd -l, unset -l, cd -n, etc. Bash renvoie souvent status 2 pour option invalide. Le sujet 42 ne demande pas toujours de gerer toutes les options, mais en correction on peut tomber sur ces comportements.

[KO] [Mandatory] pwd  -l 
   [STDOUT EXPECTED]: ''
   [STDOUT GOT]     : '/home/gpalemo/Minishell/minishell_titan_tmp'
   [EXIT CODE EXPECTED]: 2
   [EXIT CODE GOT]     : 0

Action proposee : decider avec Dounia si on vise strict sujet ou bash-like. Si bash-like, traiter les options invalides pour pwd, unset, cd, export.

Moyen4. Quote syntax edge case

Hardcore signale un cas de quote invalide ou bash sort status 2, tandis que minishell sort 0. A verifier a la main, car la ligne est volontairement tordue.

Action proposee : tester manuellement dans bash et minishell, puis verifier le lexer/parser de quotes si la difference est confirmee.

Par partie du projet

Input / prompts / mode non-interactif

  • Les prompts minishell$ et heredoc > ne polluent plus les tests redirections/heredoc.
  • Les tests heredoc de Titan sont OK.
  • Reste a appliquer la meme logique au builtin exit : pas de exit affiche si stdin n'est pas un terminal.

Builtins

  • exit : 368 KO mandatory, principalement stdout parasite exit.
  • pwd/cd/unset/export : nombreux KO sur options invalides. Priorite plus basse si vous restez strictement sur le sujet.
  • env/export sans arguments : KO nombreux, mais les comparaisons exactes d'environnement sont fragiles. Il faut verifier a la main avant de conclure a un bug.

Expansion

  • Vrai bug probable : variables unset collees qui laissent un argument vide ou espace parasite.
  • Probablement hors sujet : $$ correspond au PID dans bash, non demande par le sujet minishell classique.
  • Probablement hors sujet : $"..." et $'...' sont des syntaxes bash avancees, non demandees.

Plan conseille

  1. Corriger exit pour ne pas imprimer exit en non-interactif.
  2. Retester mandatory. Le score devrait fortement remonter.
  3. Corriger l'expansion des variables unset collees.
  4. Verifier manuellement le cas quote hardcore.
  5. Decider si vous corrigez les options invalides des builtins ou si vous les classez hors priorite sujet.
  6. Faire Valgrind manuel sur commandes ciblees plutot que se fier a la categorie leaks Titan.

Ce qui a ete corrige

CorrigePrompts et sortie en non-interactif

Le shell distingue maintenant le mode interactif du mode pipe/testeur. Les prompts minishell$ et > ne polluent plus stdout dans Titan, et exit n'imprime plus exit quand l'entree vient d'un pipe.

printf 'exit 42\n' | ./minishell
echo $?
# attendu : 42, sans texte parasite

CorrigeExpansion vide non quotee

Un mot non quote qui devient vide apres expansion est maintenant supprime des arguments. Un mot quote reste garde, ce qui correspond au comportement attendu.

echo $UNEXISTING$UNEXISTING a     # affiche: a
echo "$UNEXISTING$UNEXISTING" a   # affiche:  a

CorrigeOptions simples des builtins

Les cas invalides les plus visibles de pwd, cd, unset et export ont ete rapproches de bash : option invalide en debut de commande, status 2, et options valides simples acceptees quand necessaire.

pwd -l       # status 2
cd -n        # status 2
unset -l     # status 2
export -l    # status 2
export -a    # status 0, sans affichage parasite

Restants par priorite

A discuterExpansion de ~

Mandatory garde environ 97 KO sur ~. Bash remplace ~ par $HOME, mais ce n'est pas une obligation classique du sujet minishell 42. A faire seulement si vous voulez augmenter le score Titan.

[KO] echo ~
STDOUT attendu : /home/gpalemo
STDOUT obtenu  : ~

A verifierComparaison exacte de env

Mandatory garde environ 173 KO classes comme comparaison d'environnement. C'est souvent fragile parce que l'ordre, les variables ajoutees par le testeur ou le contexte du shell peuvent differer. Avant de corriger, il faut isoler un cas manuel vraiment faux.

Hors sujet$$, $'...', $"..."

Les 56 KO restants en expansions viennent de syntaxes bash avancees : PID avec $$, quotes speciales $'...' et localisation $"...", plus quelques lignes avec ;. Nico ne gere pas proprement ces familles non plus, donc on ne les priorise pas.

[KO] echo $$USER
attendu Titan/bash : PID + USER
obtenu minishell   : comportement simple d'expansion $USER

Hors sujetSemicolon ;

Quelques KO mandatory utilisent plusieurs commandes sur une seule ligne avec ;. Le sujet ne demande pas ce separateur, donc ce n'est pas une priorite.

Plan conseille maintenant

  1. Ne pas partir sur $$, $'...', $"..." ou ; sauf demande explicite : c'est trop bash avance pour le sujet.
  2. Faire une courte verification manuelle de env/export pour voir s'il reste un vrai bug hors comparaison fragile.
  3. Decider si ~ vaut le coup. C'est defendable de ne pas le faire, mais c'est le plus gros paquet Titan restant.
  4. Faire une passe Valgrind manuelle sur commandes representatives, plutot que se fier a la categorie leaks Titan.
  5. Avant PR : make, norminette sur les fichiers touches, puis relancer au moins mandatory/redirections/hardcore.

Integration lexer / parser / heredoc avec Dounia

Resume de ce qui a change apres le merge sur dev, pourquoi on l'a change, et ce qu'il faut expliquer a Dounia pour la suite.

Etat actuel

  • On est reparties d'une branche propre depuis le dernier dev.
  • Le projet compile avec make fclean puis make.
  • Les fichiers modifies par cette etape passent Norminette.
  • Les tests heredoc / redirections importants passent dans le vrai minishell.

Changements faits

Fichier Changement Pourquoi
srcs/main.c La loop appelle maintenant parse_tokens(shell->token, shell->env). Le parser doit recevoir l'environnement pour pouvoir ouvrir les heredocs et expanser leur contenu quand le delimiter n'est pas quote.
srcs/main.c Quand validate_syntax detecte une erreur, la loop fait maintenant seulement return. validate_syntax affiche deja le message precis et met le status a 2. Le message generique dans main.c creait un double affichage d'erreur.
srcs/parser/parser.c parse_tokens_with_env a ete renomme en parse_tokens. C'est maintenant la vraie entree du parser. Garder un nom temporaire avec with_env devenait moins clair.
include/minishell.h Le prototype officiel est maintenant t_cmd *parse_tokens(t_token *tokens, t_env *env). Le header doit refleter la vraie signature utilisee par la loop.
srcs/parser/parser_entry.c Le fichier a ete supprime. Il servait seulement de wrapper temporaire parse_tokens(tokens) vers parse_tokens_with_env(tokens, NULL). Comme la loop passe maintenant l'env, ce wrapper ne sert plus.

Pourquoi c'etait necessaire

Le heredoc est ouvert pendant le parsing des redirections. Pour un heredoc non quote, son contenu doit etre expanse comme bash : 

cat << EOF
$USER
EOF

Pour transformer $USER en sa valeur, le code heredoc doit avoir acces a shell->env. Donc l'environnement doit descendre depuis la loop jusqu'au parser, puis jusqu'a open_heredoc_redirection.

Ce que Dounia avait deja bien avance

  • Pour une commande externe seule, exec_single_external appelle deja set_fds(cmd, -1, NULL) avant exec_external.
  • Pour un builtin seul, exec_single_builtins sauvegarde stdin/stdout, applique set_fds, lance le builtin, puis restaure stdin/stdout.
  • Donc les redirections simples, heredoc, et redirections de builtins sont deja bien connectees avec les fd ouverts par le parser.

Points a dire a Dounia

  • On a modifie main.c pour passer shell->env au parser. C'etait necessaire pour l'expansion dans heredoc.
  • On a aussi retire le print generique minishell: syntax error dans main.c, parce que validate_syntax affiche deja l'erreur exacte, par exemple newline.
  • On a supprime l'ancien wrapper parser_entry.c. Si Dounia avait un appel a parse_tokens(tokens) dans une autre branche, il faudra le remplacer par parse_tokens(tokens, shell->env).
  • Sa logique set_fds fonctionne bien avec les fd ouverts par le parser. On l'a valide avec heredoc, redirections et pipes.
  • Les signaux heredoc ont l'air corrects sur Ctrl-C / Ctrl-D, mais il faudra encore tester les signaux globalement avec commandes bloquantes et pipelines.
  • Il faudra verifier avec Valgrind les leaks autour de heredoc/redirections, surtout quand plusieurs redirections remplacent les fd precedents.

Ce qui reste a faire

  • Comparer plus largement les messages d'erreur avec bash.
  • Faire des tests signaux hors heredoc : cat, pipeline, Ctrl-C, Ctrl-\.
  • Faire une passe Valgrind/leaks sur les cas heredoc et redirections.
  • Faire une Norminette plus globale avant PR finale.

Conclusion

La partie heredoc/parser est maintenant bien integree avec la loop et l'exec. Le gros changement a retenir est simple : le parser recoit maintenant l'env, ce qui permet au heredoc d'expanser correctement son contenu. Les fd ouverts par le parser sont bien utilises par l'exec actuelle.
